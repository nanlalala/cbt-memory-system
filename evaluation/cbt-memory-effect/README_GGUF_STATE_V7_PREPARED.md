# T4 native state comparison v7 — prospective entry

This entry compares the same 24 exposed constructed variants, two product
versions and two arms: 96 logical answers. It uses the official Qwen2.5-7B
Instruct GGUF Q4_K_M weights with the separately declared native T4 execution
condition. Earlier CPU answers, scores, source files and budgets are preserved.

No main study is initialized, frozen or started by preparing this code. Before
initialization, the new GPU reader must finish all eight original reading
fixtures with eight EOS-complete exact typed answers and valid actual offload
evidence. CPU gate success is not treated as GPU gate success. The GPU gate's
eight attempts and the main study's ceiling of 57 unique attempts are separate.

## Actual GPU evidence and stable identity

The backend verifies the pinned CUDA wheel/native libraries, the observed T4
device, compiled GPU support, the actual constructor's CUDA0 full-layer offload
log, and the GPU memory increase. The real process stderr must be directly
redirected to a fresh regular file; Python stream interception is not used.
The constructor's exact byte range and SHA256 are retained in its proof.

Per-load log paths, byte ranges and memory values stay in the actual setup
receipt and `backend.gpu_execution_proof`. Only the stable hardware/runtime
execution condition enters model and cache identity. Otherwise identical
requests would incorrectly acquire different generation keys after each load.

Every main run binds its own phase setup receipt, GPU proof and gate
revalidation SHA. Proofs are checked before admissions. The native gate's old
and fresh load proofs must each validate against the same stable condition;
their dynamic memory and log details are deliberately not equated.

## Running and preserving evidence

Initialization requires externally observed SHA256 values for the completed
GPU gate protocol, result and original authentication receipt. Failed,
incomplete or unproved gate artifacts block creation of the main directory.

`run-side --side before|after` and `score` each require
`--constructor-log-path` naming the file actually receiving that process's OS
stderr. Each model-load phase has its own exclusive claim, journal and setup
receipt. The original frozen gate runner is used read-only with
`original_load=False` to reproduce its complete native outputs using the fresh
main backend before any main answer admission.

Fresh before/after product preparation preserves pinned source commits,
permissions, recent six messages, original quotations, source ranking and the
shared request budget. The unchanged question-field policy only omits
redundant unrelated known fields whose exact evidence remains in retained
quotations. New requests are registered through actual source transactions and
Gates, retaining the original fresh database paths and writer identity.

The entire 96-row grid and its actual deduplicated request counts freeze before
inference, within the independent ceiling of 57 unique attempts. Every logical
cache reuse passes live source checks and native output authentication. All 96
answers authenticate before main labels are parsed. Primary scoring requires
an observed native EOG, sole-answer whole JSON and exact typed equality, with
no response repair or post hoc adapter.

## Resources and failures

Actual native vectors, yielded token IDs, EOG, original bytes, prompt/output
counts and failure observations are retained. A failed evaluation's input
vector length is reported separately from whether processing completed.
Unknown or failed attempts are not automatically retried. Withdrawn output is
discarded while observable usage and elapsed time remain recorded.

Whole-side preparation, prepare/render/audit child durations, whole answer
phases, cache validation, native generation, setup and gate revalidation are
measured separately. Full immutable SHA validation is preserved, including the
large CUDA wheel; its cost is timed explicitly and is included in answer/cache
processing. Nested components are not added twice. Untimed ingestion,
projection, indexing and packing substages remain null.

Tests use tiny invented metadata, fake native engines and character tokens.
They do not establish model efficacy or clinical quality. Actual execution is
restricted to genuine hosted Colab; no secret or paid inference API is used.
